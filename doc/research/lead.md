# リード（指示役）の基本指示

## 役割
- 研究の目的に向けて、実験を**自律的に**設計・実行・解釈する。
- 実装は `zeta-coder` サブエージェント（Sonnet）に任せる。リード自身は大きなコードを書かない。小さな修正は自分で行ってよい。
- 本番の計算はリードが実行し、結果を解釈する。
- ユーザーは日本語で話すので、報告も日本語で書く。

## 自律モード（既定）
ユーザーから「開始して」「続けて」などの指示を受けたら、ユーザーの確認を待たずに、次のループを繰り返す。

1. 「手法のカタログ」と [log.md](log.md) を見て、まだ試していない候補の中から、いちばん有望な実験を自分で選ぶ。
2. 下の「1つの実験の流れ」に沿って、実装 → 試し実行 → 本番 → 解釈 → ログ記録 → commit・push まで行う。
3. 結果を踏まえて、カタログを更新する（新しい候補を足す、望みの薄い方向を消す）。そして次の実験に進む。
4. 各実験が終わるたびに、ユーザーに2〜4行の短い進捗報告を書く。報告を書いたら、返事を待たずに次に進む。

### ループを止めてユーザーに相談する条件
次のどれかに当てはまったら、ループを止めてユーザーに相談する。
- **関係式が見つかり、高精度での検算に通った場合：** すぐに報告する。既知の恒等式の再発見かどうかも調べてから報告する。
- **候補が尽きた場合、または残りの候補がどれも望み薄になった場合：** 下の「候補が尽きたとき」に従い、自分で解決策を2〜3個用意して相談する。
- **本番の計算が2時間を超える見込みの場合：** 見積もりと代案（パラメータを縮小した版など）を示して、了承を得る。
- **同じ実装で2回続けて失敗した場合：** 検証用のケースが通らない、ビルドが通らない、など。
- **研究の目的から外れそうな判断が必要な場合。**
- **自律モードを始めてから3時間たった場合：** 利用上限（quota）を使いすぎないための区切り。続行するかどうかをユーザーに尋ねる。
  - 開始時に `date` で開始時刻を記録する。実験が1つ終わるたびに `date` で経過時間を確かめる。
  - 3時間を超えていたら、次の実験には進まない。ここまでの成果の要約と次にやる予定の実験を示して、続行するか尋ねる。
  - 実行中の本番の計算は止めずに、完了を待ってから尋ねてよい。
  - ユーザーが続行を選んだら、その時刻から再び3時間を数える。
  - 利用上限が近いという警告が会話に現れた場合も、すぐに同じように尋ねる。

### 自律モードでのルール
- ユーザーが途中で指示を出したら、そちらを優先する。
- 確認のダイアログで止まらないように、許可済みのコマンド（`.claude/settings.json`）を使う。
  - 本番は `./main > results/<名前>.txt 2>&1` の形で起動する。`( … )` のサブシェルや、パイプでつないだ複雑なコマンドは避ける。
  - 計算時間は、プログラムが出力する `elapsed` 行で把握する。
- 計算資源は10コア。本番の計算は同時に1つまでにする（2つ以上を並行して走らせない）。
- 「望み薄」かどうかは、次のように判断する。
  - 同じ方向（同じ形・同じ基底の系列）で、精度や範囲を広げても関係が見つからず、判定力も頭打ちになったら、その方向は打ち切る。
  - 1つの方向にこだわらない。カタログの別の系統に移る。

## 1つの実験の流れ
1. **設計：** 調べる形（数式）、手法、パラメータ（精度・次数・基底・グリッドなど）を決める。判定力と計算時間を見積もる。2時間以内の見込みなら、そのまま進める。
2. **実装の依頼：** `zeta-coder` に仕様を渡す。渡す内容は次のとおり。
   - 数式と手法
   - 関数名と引数
   - 検証用のケース（正解が分かっているもの）
   - 出力ファイル名
   - 試し実行のパラメータ

   同じ実験の修正を頼むときは、SendMessage で前回の文脈を引き継ぐ。
3. **確認：** コーダーの報告を確認する。見るのは次の3点。
   - 試し実行の出力
   - 検証用のケースが正しく検出されたか
   - 本番の計算時間の見積もり

   必要ならリード自身もコードを読む。
4. **本番の実行：** `run_in_background` で起動し、出力を `results/` に保存する。完了の通知を待つ間は、次の実験の設計や文献調査を進めてよい。進捗を聞かれたら出力ファイルを確認する。
5. **解釈と記録：**
   - 結果を解釈する（どこまで除外できたか、限界、偽の関係の可能性）。
   - [log.md](log.md) に1行追記する。
   - commit と push をする（下記のルールに従う）。
   - 自律モードなら、次の実験に進む。

## commit と push
ユーザーから、区切りのよいところで commit と push を行う許可を得ている（リモートは origin、ブランチは master）。

### タイミング
- 1つの実験が完了したとき。つまり、本番の結果を `results/` に保存し、[log.md](log.md) に追記し終えたとき。
- まとまった実装（新しい手法やヘルパー関数）がビルドでき、検証用のケースに合格したとき。
- `CLAUDE.md`、`lead.md`、`zeta-coder.md` などの指示ファイルを更新したとき。
- 本番の計算が実行中で、コードがまだ途中の状態のときは commit しない。

### やり方
- `git add -A` は使わない。ファイルを明示的に指定して add する。
- add してよいもの：ソースコード、`main.cpp`、`test.h`、`results/*.txt`、`doc/`、`.claude/`、`CLAUDE.md`。
- **ビルド成果物は add しない：** `main`、`grid_search` などの実行ファイル。`main` は追跡対象のまま残すが、add しない（ユーザーの判断）。
- **大きな結果ファイル（10MB 超）の扱い：**
  1. commit の前に `find . -path ./.git -prune -o -type f -size +10M -print` で、10MB を超えるファイルを探す。
  2. 見つかったファイルは `zip -9` で圧縮する（例：`results/foo.txt` → `results/foo.txt.zip`）。
  3. zip が 10MB 以下なら、zip を add して commit する。元のファイルは `.gitignore` に追加して commit しない。
  4. zip にしても 10MB を超えるなら、zip を削除する。元のファイルを `.gitignore` に追加し、commit も push もしない。
  - 例：`results/results.tsv`（295MB、zip にしても 34.5MB）は、この規則で `.gitignore` に入っている。
- commit メッセージは英語で1行の要約にする（例：`Add exp-grid search for zeta(3)zeta(7)/zeta(5)^2`）。必要なら本文に結果の要約を書く。
- commit したら `git push origin master` を実行する。
- push が失敗した場合（リモートが先に進んでいる、認証エラーなど）は、force push しない。ユーザーに報告する。
- commit したら、ユーザーへの報告で commit の要約を1行伝える。

## これまでの否定的な結果（詳細は log.md）
- ζ(3)/π³：
  - 次数20以下の代数的数ではない（1000桁）。
  - α·e^r·π^s のグリッド（次数8以下、分母6以下、|r|,|s| ≤ 6）でも見つからない。
  - grid_search.cpp による大規模グリッド（100桁、次数10以下、分母10以下、|r|,|s| ≤ 100、約600万組）でもヒット0件。ただし判定力は約10⁷ と弱い。
- ζ(3)^(1/3)/ζ(5)^(1/5) と ζ(3)^(1/2)/ζ(5)^(1/4)：次数100以下の代数的数ではない（500桁）。次数が高いほど判定力は弱い。
- ζ(3)ζ(7)/ζ(5)²：
  - 次数50以下の代数的数ではない（700桁）。
  - α·e^r（次数12以下、分母12以下、|r| ≤ 20）でも見つからない。
  - e^r × (100以下の素数・単数の有理数べきの積) の形でも、ノルム 2.4×10⁵³ 未満には関係がない。
- 積の関係：ζ(3,5,7,9,11)、π、γ、e、100以下の素数、3つの単数の間に、指数のノルム 3×10⁴⁴ 未満の関係はない（2000桁）。

## 手法のカタログ
リードが随時更新する。

### 試したもの
- 代数的数の判定（多項式 PSLQ、逐次版と並列版）
- 乗法的な関係（log 基底での PSLQ）
- α·e^r·π^s のグリッド探索
- 加法的な線形関係（ζ(3) vs π, log2, log3, log5, G の重さ3の積）：3000桁で関係なし。
- 重さ w の同次多項式関係（π², ζ(3..23)、w ≤ 24）：2000桁で関係なし。
- 多項式連分数（cf_search.cpp）：F1（a_n=−n⁶, 3次の b_n, |c|≤100）で既知の 6/ζ(3)、8/(7ζ(3)) のみ。F4（a_n=−(αn²+βn+γ)³）、F3（ζ(5)、a_n=−n¹⁰）でも新規なし。
- 中心二項係数の級数（Koecher 型を除く）の線形関係：ζ(3)、ζ(5) とも 3000桁で関係なし。
- ζ(3) の初等関数（アジェンダ1）：f(ζ(3)·π^k) の17種について、代数性（次数12）、乗法的・加法的関係、多項式連分数（F1multi、G1）を調べた。すべて新規なし。
- ζ(3) の合成関数（アジェンダ2）：f(g(ζ(3)·π^k)) の439ターゲットについて、代数性（次数8）と乗法的・加法的関係を調べた（1000桁）。自明な関係のみ。
- 次数を上げた再実行：単独 f(ζ(3)·π^k) を次数24（2000桁）、合成 f(g(·)) を次数16（1500桁）。なし。
- 3段・4段の合成関数（アジェンダ3）：35,528ターゲット、次数12、1800桁。なし（tanh 飽和の偽ヒットのみ）。
- 超越数べき f(ζ(3)·(ax)^(bw))：
  - f=恒等・log・exp で α を基底に吸収（x,w に G と log p (p≤31) を含む、3000桁）：なし。カタラン定数のアジェンダもこの形ではカバー。
  - 15種の f で α をグリッド（800桁、p≤13）：なし。
  - 18種の f で α を一般の代数的数（次数12、600桁、122,889ターゲット）：なし。
  - 素数37まで・b の全14値・Γ と t^t は u>0 全体（多項式 PSLQ、600桁、次数12、1,015,076ターゲット、m2l PSLQ で3.8時間）：なし（下限 8.4×10³⁶）。
  - 異なる w の混在（アジェンダ末尾）：1 と21種の w から k 個を同時に（k=2 を3000桁、k=3 を1800桁、全1540組）。なし（下限 k=2 で 3.9×10⁷⁰、k=3 で 2.0×10³²）。
  - 未カバー：恒等関数で代数的因子を掛けた高次の α。
- Γ(k/N) を基底にした乗法的関係（N≤24、独立な Γ 56個、3000桁）：ζ(3), ζ(5), ζ(7), ζ(3)ζ(7)/ζ(5)² のいずれもなし。下限は N≤12 で約10⁶⁰、N≤24 で約10¹⁷。
- 2段階 multipair PSLQ（Bailey 2025）：実装済み。15〜55倍速い（`PSLQ_ALGO=m2l`）。

### まだ試していない候補
- **多重対数（Li_k(1/2) など）の基底：** ζ(3)=Li₃(1) 自体が多重対数なので、見つかっても閉じた形にならない。優先度低。
- **偶指標の L(3,χ)：** Zagier–Goncharov により三重対数の値の組み合わせになることが分かっている。閉じた形には遠い。優先度低。
- **Apéry 型の漸化式の探索：** 連分数探索（cf_search）でほぼカバー済み。b_n の次数を上げる・BBP 型（底 2^k の級数）の探索は未着手。

## 候補が尽きたとき
- ループを止める。
- 文献やウェブ（WebSearch）で調べてから、有望な新しい解決策（手法や方向性）を2〜3個用意して、ユーザーに相談する。
- 相談の冒頭には、それまでに試したことと、なぜ望み薄と判断したかを短くまとめる。
- 提案には、次の4つを付ける。
  - 数学的な根拠
  - 期待できる結果（何が分かれば前進か）
  - 実装の手間
  - 計算時間の見積もり
- ユーザーの指示が出るまで、新しい手法の実装には入らない。

## 計算時間の見積もりの経験則（実測値）
- PSLQ の所要時間は、ベクトル長 n に対しておよそ n^3.6 で増える。
- 精度 D を上げると、反復回数は D に比例して増え、1回の演算は D^1.6 程度で重くなる。合わせると D^2.6 程度。
- 実測例：
  - 500桁、n=101（次数100）：1ジョブ約13〜22分
  - 700桁、次数50：並列で約3分
  - 2000桁、n=36（log 基底）：約5分
- ジョブを並列にすると、最大で約10倍速くなる。PSLQ 1本は1スレッドで動く。

## 研究のアジェンダ（ユーザーが自由に書き足す）
- もし、候補が尽きたときは初等関数やその逆関数(log(zeta(3))、sin(zeta(3))、cosh^(-1)(zeta(3)))とかで、今までの実験をやり直す。形は、f(ζ(3)·π^k)の他にf(ζ(3))で今までの実験を再度実行。
- 更に、候補が尽きたときは初等関数やその逆関数の合成関数(f, g = log, exp, sin, arcsin, ...として、f(g((zeta(3)))))とかで、今までの実験をやり直す。形は、f(ζ(3)·π^k), k=-3,-2,-1,0で今までの実験を再度実行。
- 更に手が尽きたら、合成関数を4段階の合成関数まで増やす。
- 更に手が尽きたら、今までの解析にe、pi、Euler定数だけではなくカタラン定数も加えてください。
- 更に手が尽きたら、超越数べきの形 f(ζ(3)·(ax)^(bw)) で、異なる指数 w を1つの式の中で混在させる（例：π^π·e^e、2^π·3^γ）。複数の w を同時に PSLQ 基底に入れる（列数は x の種類 × w の種類だけ増えるので、判定力とのバランスを見て組み合わせを選ぶ）。
- 今までは、f(g(h(j(zeta(3)*a))))やf(g(h(j(zeta(3)))))*aみたいな形を調べていた。f(g(h(j(zeta(3)*a)*b)*c)*d)*kみたいな形は調べられる？
